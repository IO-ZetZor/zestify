# Zesti CLI Replacement Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the Caelestia CLI runtime dependency with the standalone `zesti` CLI while preserving the existing Zestify shell and every command it currently uses.

**Architecture:** A standard-library Python package owns parsing, XDG state, Quickshell lifecycle, Matugen palette conversion, wallpaper operations, desktop utilities, diagnostics, and migration. `bin/zesti` is canonical and `bin/zestify` silently normalizes the old flat command interface into the same parser. State writers, QML watchers, and installer handoff move from Caelestia to Zestify paths in one release.

**Tech Stack:** Python 3.14 standard library, POSIX/Bash launchers, Matugen 4.2+, Quickshell 0.3+, QML/Qt 6, Hyprland IPC, ffmpeg, unittest.

**Spec:** `docs/superpowers/specs/2026-11-07-zesti-cli-design.md`

## Global Constraints

- `zesti` is primary; `zestify` remains a silent compatibility entry point.
- Keep Quickshell config name and IPC target exactly `zestify`.
- Do not install a `caelestia` command or import/call Caelestia at runtime.
- Do not delete or modify Caelestia state; migration is copy-only and idempotent.
- Use XDG-aware `zestify` config/state/data/cache paths and atomic state writes.
- Generate dynamic palettes with `matugen`; retain the last valid scheme on failure.
- Preserve current visible shell behavior, surface names, keybindings, and session behavior.
- Use standard-library Python; desktop integrations are external executables with explicit diagnostics.
- Keep GPL-3.0-only licensing and attribute adapted Caelestia data/code in `NOTICE`.
- Use TDD, run the focused test after each change, and commit each completed task.

## Review Focus

- A running or half-stopped Quickshell instance must not produce a duplicate or make restart silently skip launch; Task 2 tests instance enumeration and teardown timeout behavior.
- Malformed/partial Matugen JSON and failed video-frame extraction must leave the last valid scheme and wallpaper state untouched; Tasks 3 and 4 test both failures.
- Untrusted monitor connector names must not escape the monitor state directory; Task 4 tests filename slugging with separators and Unicode.
- User cancellation or a missing optional selector/capture tool must be a clean no-op or actionable feature error, never a traceback; Tasks 6 and 7 test cancellation and missing tools.
- Interrupted migration and dirty/detached Git updates must preserve user work and remain safe to retry; Tasks 8 and 9 test marker ordering and update refusal.
